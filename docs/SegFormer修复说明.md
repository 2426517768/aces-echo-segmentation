# SegFormer 中断恢复补丁 v1.4

对应报错：`segformer_b0` 第 88/200 轮出现 `Nonfinite training loss`。这是损失中出现 NaN 或 Inf 后主动停止；截图不足以确定由混合精度、数据或其他因素引起。

## 在原目录应用

1. 关闭已报错的运行窗口，确认没有另一份训练进程运行。
2. 解压 `ACES_SegFormer_Fix.zip`，把里面的文件和 `aces`、`tests`、`docs` 文件夹合并覆盖到原来含有 `START.bat` 的目录，选择替换同名文件。
3. 保留原有 `data`、`prepared`、`runs`、`.venv` 及 `settings.json`；补丁不含这些运行数据或配置。不要另建空目录运行，不用重新下载数据。
4. 双击 **`RUN_ALL.bat`**。已完成且签名一致的训练会复用，SegFormer 从最近有效的 `last.pt` 继续。日志应显示 `Resuming segformer_b0` 及 `FP32 训练及评估`。

本次 SegFormer 训练尚未结束，请使用 `RUN_ALL.bat` 继续；`EVALUATE_ONLY.bat` 是已完成主模型训练后的单独评估入口。

## 实际改动及记录

- SegFormer 训练、验证、测试及测速显式使用 FP32。其他方法继续按原配置运行。FP32 可能增加显存与耗时，本端未在 RTX 5060 上验证该补丁的峰值显存或速度。
- 保留原数据清单、患者划分、样本顺序、标注预算、模型、学习率、优化器状态、调度器状态及剩余更新数；不修改 `settings.json` 以兼容现有冻结配置。
- 旧检查点中的 AMP 缩放器在切到 FP32 后停用。`numerical_precision.json`、新检查点中的 `precision_history` 记录原有精度及切换位置。已经以 FP16 开始的这次训练属于中途切换，后续新种子从 FP32 开始；论文应如实说明，不应写成全部从头采用同一精度。
- 已有 `best.pt` 的同一组权重先在源验证集按 FP32 重新评分，后续继续用验证分数选择最佳模型。权重张量不变，但评分及精度元数据更新，文件 SHA-256 会变化。记录在 `best_fp32_revalidation.json`。此步骤不读取测试集。
- 检查输入、损失、梯度及保存时的模型/优化器状态是否有限；验证及评估输出含非有限数时停止。不替换 NaN，不跳过异常样本，不生成替代分数。
- 若 FP32 训练仍异常，保留此前断点并写入本次运行目录的 `numerical_error.json`，含阶段、epoch、update、样本 ID 等诊断。此时保留错误日志和该 JSON 供定位；损坏断点不会被当作可用模型继续训练。
- 既有 SegFormer 的旧精度测速缓存会重测；温度和测试缓存按实际检查点签名更新。包含此前 v1.3 的测速梯度上下文修复。
