# 按你的 RTX 5060 Laptop 8GB 配置制作的运行包

适用：Windows 10/11 64 位，Intel Core Ultra 7 251HX、RTX 5060 Laptop 8GB、16GB 内存。默认单 GPU，不启动多个训练进程。

## 最短操作

1. **把整个 ZIP 解压**到本地文件夹，例如 `D:\ACES`；不要在压缩包预览窗口内运行。
2. 双击 **`START.bat`**。首次会创建独立环境、安装依赖、检查 GPU；未发现 CAMUS 数据或已有下载尚未完成时，会从已确认的官方公开来源逐个下载原始文件。已有官方数据时，可提前解压到 `data/camus/`，包含图像、标注和官方划分清单。按你已经确认的提供方许可使用数据。
3. 按下载版本的官方说明核对标签，再输入 `YES`，开始主模型训练。再次双击会接着已有检查点运行。也可单独用 `DOWNLOAD_CAMUS.bat` 预先下载。

下载器 v1.2 默认单线程；临时失败文件会暂缓并在后续轮次自动补下载。看到“30/60 秒后自动补下载”时保留窗口即可。若最终仍因网络故障停止，稍后再次启动可续传，详见 `下载修复说明.md`。

本包默认的 CAMUS 标签映射是 `0 背景 / 1 左室腔 / 2 心肌 / 3 左房`，但不同发布版必须先核对。若实际不同，在 `settings.json` 的 `data.label_map` 中填写“原值→本程序值”。代码不会凭图像外观猜标签含义。

**启动入口串起环境准备、必要的数据下载、训练、校准、评估和导出。** 本包不含数 GB 的原始影像、预训练权重或已有性能结果；首次仍需按提示完成提供方条款及标签核对。网络受限时可手动下载数据，再重新启动。

## 训练结束后报梯度错误的恢复

如果训练后测速提示 `element 0 of tensors does not require grad`，请应用 v1.3 修复后双击 **EVALUATE_ONLY.bat**，读取已有 `best.pt` 继续测速、校准、测试与导出。具体覆盖步骤见 `训练后修复说明.md`。

## SegFormer 训练中出现非有限损失的恢复

v1.4 为 SegFormer 显式启用 FP32 及数值检查，保留已有断点与训练状态。应用 `ACES_SegFormer_Fix.zip` 后，在原目录双击 **RUN_ALL.bat** 继续，保留原 `settings.json` 与 `runs`。详见 `SegFormer修复说明.md`。如果 FP32 下仍异常，程序停止并保存 `numerical_error.json`，需要继续定位。

## 启动入口对照

| 双击文件 | 实际执行内容 |
|---|---|
| `START.bat` | ACES，25% 训练患者标签，seed=17；200 epochs×100 次参数更新；训练后校准、测试、导出 |
| `RUN_ALL.bat` | 33 个预设核心实验：25% 标签的 8 个方法×3 种子，加 100% 标签的 3 个方法×3 种子；依次运行与续跑 |
| `CHECK_GPU.bat` | CUDA 内核、ACES 与教师前反向显存试跑；不训练真实数据 |
| `SMOKE_TEST.bat` | 很小的合成几何数据流程自检；输出在 `smoke_only/`，不进入真实实验汇总 |
| `RUN_TESTS.bat` | 软件测试，包括患者隔离、指标、医学格式读取与中断续跑 |
| `PREPARE_DATA.bat` | 只做真实数据读取、检查及缓存 |
| `EVALUATE_ONLY.bat` | 读取主模型已有权重，完成测速、校准、测试及导出；不调用训练，不存在模型时停止 |
| `DOWNLOAD_CAMUS.bat` | 从官方公开单文件端点下载；自动重试、续传、校验；使用提供方当前许可 |

`RUN_ALL.bat` 的“全部”指本包已实现的核心实验组合，**不表示原方案中的 AP-Net 已经完成复现**。本包实现 ACES、U-Net、Mean Teacher、SegFormer-B0 与 ACES 匹配消融。AP-Net 在输出中列为未完成，不填数字，详情见 `docs/APNet状态.md`。

## 第一次安装

- 自动优先使用已有 Python 3.10–3.12；找不到时，从 python.org 下载带有效签名的 Python 3.12.10 安装器，安装到包内 `runtime/`，不要求管理员权限，不改系统 PATH。
- 创建包内 `.venv/`，从 PyTorch 官方 CUDA 12.8 索引安装固定版本 `torch==2.7.1`，其余依赖固定在 `requirements.txt`。
- RTX 50 系列不能仅凭“torch 能导入”认定兼容；代码会真的执行 CUDA 运算与反向传播。需要可兼容的 NVIDIA 驱动；若失败，按错误提示更新驱动后重试。
- 首次依赖下载有数 GB。后续启动复用环境。建议主模型运行预留至少 30GB，完整组合预留至少 80GB；具体由数据格式、缓存与检查点大小决定。

安装依据：[PyTorch Blackwell/CUDA 12.8 官方说明](https://pytorch.org/blog/pytorch-2-7/)、[官方历史版本安装命令](https://pytorch.org/get-started/previous-versions/)。固定版本用于本实现复现，不表示它是最新版本。

## 本机默认资源设置

| 设置 | 默认值 |
|---|---|
| 输入 | 保宽高比缩放并补边至 256×256 |
| 显存策略 | 其他方法按配置采用 FP16 自动混合精度；SegFormer 自 v1.4 起采用 FP32。微批量 2；梯度累积 2 次，有效批量 4 |
| 模型 | 通道 32/64/128/256/512；图 16×16 节点、128 维、4 头 |
| CPU | 4 个计算线程；同步读取，不启动多进程 DataLoader |
| 内存缓存 | 最多 32 条样本，避免一次加载整库 |
| 检查点 | 每 25 次完整参数更新及每个 epoch 保存；不保存中断中的半个更新 |
| 选择模型 | 只用 CAMUS 验证集患者级 macro Dice；教师方法只在预热后进入 checkpoint 选择 |

8GB 是否足够仍以你本机 `CHECK_GPU.bat` 和实际训练为准。当前交付在 CPU 上测试，未在你的 Windows 或 RTX 5060 上实测。训练时接电并保持系统不睡眠；可以关闭显示器。

如果显存不足，先关闭占用显存的其他程序。还不足时，将 `micro_batch` 改为 1，`effective_batch` 保持 4，并把 `paths.runs` 改为新的目录名再开始；代码不会把已有不同配置混为同一次续跑，也不会自动降低图像分辨率。

## CAMUS 划分

优先识别官方 `subgroup_training.txt`、`subgroup_validation.txt`、`subgroup_testing.txt`，也支持 `train/training`、`val/validation`、`test/testing` 及相应 `_patients` 文本患者清单。无单独验证集时，只在官方训练/开发患者中固定划出 50 人验证；不触碰官方测试患者。所有帧、时相、视图按患者隔离。

若未识别清单，把**真实官方名单**整理为下列 JSON，保存到 `data/splits.json`，设置 `settings.json → data.split_file` 为 `data/splits.json`：

```json
{
  "train": ["填真实训练患者ID"],
  "val": ["填真实验证患者ID"],
  "test": ["填真实测试患者ID"]
}
```

这里是格式说明，不能把示例字符串当作患者。不得按 `patient0001–0400` 等编号范围猜官方划分；也不得把旧版 train/test 中可能重名的患者文件夹直接合并。清单冲突、重复 ID、缺少参考标注或未知标签值都会停止处理。

官方数据入口：[CAMUS](https://www.creatis.insa-lyon.fr/Challenge/camus/)。官方网页中的 500 例是发布规模，本次实际纳入例数从本地文件重新统计，写在 `prepared/camus/dataset_audit.json`。

## HMC-QU 外部验证

没有准备 HMC-QU 时，主模型照常训练，外部状态为 `not_run`。

如需运行：从[维护者发布页](https://www.kaggle.com/datasets/aysendegerli/hmcqu-dataset)合法获取数据，核对左室壁的真实标注含义，按 `docs/HMC_QU映射说明.md` 填好每帧路径和患者映射，再将模板另存为 `data/hmc_qu/external_manifest.csv`。在 `settings.json` 中设置 `data.external_target` 为 `myocardium` 或 `epicardial_area`。

外部数据不会用于训练、先验拟合、模型选择或温度拟合。未有可靠像素间距时外部距离只报 pixel。标注不一致时不输出伪造的三类外部分割结果。

## 看哪里

- `logs/`：每次运行完整文本日志。
- `runs/方法_labels025_seed17/`：`best.pt`、可续跑的 `last.pt`、冻结配置、标签子集、先验、硬件信息、训练曲线 CSV。
- 同一目录的 `test/`、可用时的 `external/`：逐帧逐类、逐患者、分层指标 CSV、摘要 JSON、预测标签 PNG 与左右对照叠加图。叠加图左侧参考，右侧预测，仅供检查。
- `temperature.json`：只在源验证集抽样拟合的温度及来源；测试校准指标按原生网格全部像素计算。
- `latency.json`：batch=1 的模型前向计时，明确排除 I/O、预处理与机器人控制。
- `results/RESULTS.md`、`results/results_by_method.csv`：实际完成的结果；三个种子齐全时才生成跨种子配对患者 bootstrap 对比。
- `results/external_status.json`：缺少外部数据时记录未运行，不填零分。

运行不会保证 ACES 比任何基线好；所有正负结果原样保留。旧 E1–E6 数值不在代码中。测试通过不代表临床效果已经验证。

## 停止与续跑

在训练窗口按 Ctrl+C；退出后重新双击同一启动文件。最多回退到最近保存的 25 次更新检查点。`last.pt` 恢复学生、教师、优化器、学习率、混合精度状态与采样随机状态。配置或数据清单变化时拒绝混用旧检查点。

不要同时双击多个训练入口。若断电留下 `pipeline.lock`，确认没有 Python 训练进程仍在运行后，删除这个锁文件再启动；不要删除 `runs/` 中的检查点。

当前不提供训练完成时间保证；试跑后根据日志中的真实耗时估算。没有实际训练结果时，不将空表或合成自检结果填进正文。
